# دورة حياة البيانات في Elections360

يصف هذا المستند رحلة البيانات العربية داخل النظام منذ توليدها وحتى أرشفتها.

## 1. التهيئة (Seeding)
- استخدام Faker مع اللغة `ar_SA` عبر أوامر مثل `generate:arabic-test-data` ومصانع Eloquent.
- إنشاء الكيانات الأساسية: الحملات، المتطوعون، الناخبون، الأنشطة، والإشعارات.
- تسجيل عملية التهيئة في `factory_audit.md` لضمان التتبع.

## 2. التفاعل (Interaction)
- يتم استهلاك البيانات عبر واجهات API (`/api/v1/*`) وتعرض في React.
- العلاقات بين الكيانات (الحملة ← الأنشطة ← الناخبون) يتم التحقق منها بواسطة `integration:verify`.
- يتم رصد الأداء عبر `api:profile` للتأكد من صلاحية نقاط API تحت الضغط.

## 3. التحديث (Update)
- يعتمد النظام على أوامر Artisan ومهام مجدولة لتحديث مؤشرات الأداء والأنشطة.
- أي تغيير في المخطط يتم رصده عبر `schema:verify` ويتطلب مزامنة للأنواع الأمامية.

## 4. الإشعارات (Notifications)
- يتم توليد التنبيهات تلقائيًا للمتطوعين/المستخدمين وتوثيقها في `notifications`.
- تقرير دورة الحياة (`lifecycle_report.md`) يؤكد استمرار الإشعارات بعد تحديث الحالة.

## 5. الحذف والأرشفة (Soft Deletes & Archiving)
- يتم محاكاة الحذف باستخدام `lifecycle:test` لضمان عدم فقد العلاقات الحرجة.
- التراجع عن التجارب يتم داخل معاملة (Transaction) للحفاظ على بيئة الاختبار.
- التقارير المحدثة تحفظ في `storage/logs` ويمكن أرشفتها دوريًا.

> **توصية:** قم بتشغيل أوامر التكامل بعد كل تحديث على الواجهة الأمامية أو المخطط للتأكد من اتساق دورة حياة البيانات.
