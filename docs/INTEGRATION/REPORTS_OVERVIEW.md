# نظرة عامة على تقارير التكامل

تولّد منصة Elections360 أربعة تقارير رئيسية أثناء فحوصات التكامل. هذا المستند يوضح الغرض من كل تقرير ومتى يتم تحديثه.

| التقرير | الموقع | الجهة المنتجة | الوصف |
| --- | --- | --- | --- |
| `schema_audit.md` | `storage/logs` | `php artisan schema:verify` | يلخص حالة جداول قاعدة البيانات مقارنة بالمخطط المرجعي. |
| `factory_audit.md` | `storage/logs` | سكربتات بيانات المصانع | يعرض حالة بيانات المصنع العربية ومؤشرات الاكتمال. |
| `integration_report.md` | `storage/logs` | `php artisan integration:verify` | جدول موحد يبين مطابقة المخطط، الأنواع، العلاقات، والتقارير. |
| `api_profile.md` | `storage/logs` | `php artisan api:profile` | يقدم متوسط زمن الاستجابة وأحجام الحمولات لأكثر نقاط API نشاطًا. |
| `system_unified_report.md` | `storage/logs` | `php artisan logs:unify` | تقرير مختصر يجمع المخرجات السابقة مع حالة الجاهزية. |
| `lifecycle_report.md` | `storage/logs` | `php artisan lifecycle:test` | يعرض تمثيل JSON لدورة حياة الكيانات أثناء المحاكاة. |

## تحديثات يومية مقترحة

1. تشغيل أوامر التكامل الأربعة.
2. مشاركة `system_unified_report.md` مع فريق التشغيل.
3. أرشفة التقارير السابقة في نظام إدارة الوثائق.

> **تنبيه:** يجب مراجعة التوقيت ضمن كل تقرير للتأكد من أنه ضمن آخر 24 ساعة لتفادي النتائج القديمة.
