# خطة تنظيف وإعداد قاعدة البيانات للإطلاق الإنتاجي

يوضّح هذا الدليل تسلسلًا منسقًا للأوامر والخطوات التي تساعدك على بناء بنية قاعدة البيانات النهائية انطلاقًا من ملفات الـ **migrations** الحالية وتنظيف أي ملفات مساعدة داخل مجلد الـ **Blueprint**.

## 1. مراجعة ملفات الـ Migrations
1. افتح جميع الملفات داخل `database/migrations`.
2. وحّد كل الأعمدة الدائمة في ملف إنشاء الجدول الأصلي بدلًا من الاعتماد على ملفات لاحقة لإضافة الأعمدة نفسها.
3. احذف أي ملفات تجريبية أو غير مستخدمة.

> **ملاحظة:** احتفظ فقط بالملفات التي تعبّر عن الشكل النهائي للقاعدة.

## 2. ترتيب ملفات الـ Blueprint (إن وُجدت)
1. مرّ على الملفات الموجودة داخل مجلد `Blueprint` أو أي مجلد مشابه.
2. احذف الدوال أو الكلاسات غير المستخدمة.
3. وحّد أي وظائف مشتركة في ملف واحد ليسهل استدعاؤها لاحقًا.

## 3. توليد مخطط الإنتاج النهائي
بعد ترتيب الملفات، نفّذ الأمر التالي لمسح القاعدة ثم إعادة إنشائها بالشكل الجديد:

```bash
php artisan migrate:fresh
```

هذا الأمر يقوم بما يلي:
- إسقاط جميع الجداول الحالية.
- إعادة تشغيل ملفات الـ migrations بعد تنظيفها.

## 4. (اختياري) تعبئة البيانات التجريبية
إذا كنت تستخدم seeders، يمكنك تنفيذ الأمر:

```bash
php artisan db:seed
```

## 5. التحقق من الحالة النهائية
تأكد من أن جميع ملفات الـ migrations تم تنفيذها بنجاح عبر الأمر:

```bash
php artisan migrate:status
```

## 6. إنشاء لقطة للبنية (اختياري)
في حال رغبت بإنشاء لقطة جاهزة يمكن استخدامها مباشرة في بيئة الإنتاج، استخدم الأمر:

```bash
php artisan schema:dump
```

سيتم حفظ ملف SQL يعكس بنية الجداول الحالية داخل مجلد `database/schema`، ويمكن استيراده لاحقًا بدلًا من تشغيل كل ملفات الـ migrations من الصفر.

## 7. تثبيت الحالة في نظام التحكم بالنسخ
بعد تنفيذ الخطوات السابقة والتأكد من سلامة القاعدة:

1. شغّل الاختبارات والتأكد من نجاحها.
2. أنشئ commit جديد يحتوي على ملفات الـ migrations والـ blueprint بعد تنظيفها.
3. ادفع التغييرات إلى المستودع ليتمكن باقي أعضاء الفريق من بدء العمل على النسخة الإنتاجية المعتمدة.

باتباع هذه الخطوات ستحصل على قاعدة بيانات نظيفة ومنظمة تعكس الحالة الإنتاجية النهائية مع الحفاظ على إمكانية إعادة البناء بسهولة في أي بيئة أخرى.
