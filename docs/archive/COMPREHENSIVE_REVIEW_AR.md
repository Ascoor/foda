# مراجعة شاملة لمشروع FODA / Elections360 الموحد

## 1. نظرة عامة على الهيكل العام
- المشروع يجمع واجهة React + TypeScript مبنية عبر Vite مع واجهة برمجة تطبيقات Laravel 8.
- وثائق الجذر توضح الدمج بين مشروعى FODA وElections360 مع 12 وحدة وظيفية وخيارات تشغيل مرنة (محلي، Docker، سكريبت موحّد).【F:README.md†L1-L66】【F:README_UNIFIED.md†L1-L84】
- السكريبت `start.sh` يهيئ بيئة التطوير بالكامل (تحقق من التبعيات، تثبيت الحزم عند الحاجة، تشغيل الواجهة على 8080 والواجهة الخلفية على 8000).【F:start.sh†L1-L82】

## 2. الواجهة الخلفية (Laravel)
- جميع نقاط النهاية تحت البادئة `/api/v1` مع مصادقة Sanctum وصلاحيات Spatie للأدوار (مسارات تسجيل، تسجيل خروج، إدارة ملف شخصي، وتحميل صورة).【F:backend/routes/api.php†L38-L73】
- وحدات العمل الأساسية تغطي الأنشطة، التحليلات، المناطق الجغرافية، الأتمتة، اللجان، الفعاليات، المالية، الإعدادات، الرسائل النصية، التحليل الرباعي SWOT، الفرق، الأعضاء، المتطوعين، والناخبين. هناك أيضاً مساحة `ec` لإدارة حلقات الانتخابات (انتخابات، مناطق، لجان، مرشحين، ناخبين، وكلاء، متطوعين، ملاحظات، حملات، إعدادات).【F:backend/routes/api.php†L74-L119】
- مثال التحليلات يستخدم التخزين المؤقت لخمس دقائق ويجمع بيانات الأنشطة والمناطق والمتطوعين لبناء لوحة تحكم (مناطق، اتجاهات دعم، توزيع البلاغات) مع واجهة توقعات منفصلة تدعم أفق حتى 30 يوماً.【F:backend/app/Http/Controllers/Api/V1/AnalyticsController.php†L1-L119】【F:backend/app/Http/Controllers/Api/V1/AnalyticsController.php†L120-L191】
- وحدة المالية توفر CRUD كامل مع ربط بفئات الإنفاق ومسار تقرير يقبل مرشحات التاريخ.【F:backend/app/Http/Controllers/Api/V1/FinanceController.php†L1-L74】
- وحدة المصادقة تدير تسجيل الدخول، التسجيل للمشرفين، تحديث الملف الشخصي، وتدوير الرموز المميزة باستخدام Sanctum.【F:backend/app/Http/Controllers/Api/V1/AuthController.php†L1-L120】
- نماذج Laravel موزعة بين كيانات المنصة العامة (نشاط، منطقة، متطوع، SMS...) ومجلد فرعي `ElectionCircle` للكيانات المتخصصة (وكيل، حملة، لجنة...).【F:backend/app/Models†L1-L14】【F:backend/app/Models/ElectionCircle†L1-L11】
- وثيقة مراجعة CRUD تؤكد تطابق أغلب وحدات الواجهة مع واجهات `/api/ec/*` وتبرز الوحدات التي ما تزال تعتمد بيانات وهمية (الوكلاء، المتطوعون، الملاحظات، الحملات، المناطق الجغرافية) وتوصي بربطها فعلياً.【F:CRUD_API_REVIEW.md†L1-L52】

## 3. الواجهة الأمامية (React + TypeScript)
- مهيكلة حول `src/modules` لكل وحدة وظيفية (لوحة تحكم، انتخابات، لجان، متطوعين، مراقبة...) مع مكونات مشتركة ضمن `src/components` وسياقات للحالة العالمية مثل المصادقة واللغة والثيم.【F:README.md†L8-L46】【F:frontend/src/modules†L1-L1】
- سياق المصادقة يتعامل مع حالة المستخدم، تخزين التوكن في `localStorage`, تحديث التوكن على الطلبات، وتوفير دوال `login`, `logout`, `refresh`، مع تطبيع للأدوار والأذونات القادمة من الـAPI.【F:frontend/src/contexts/AuthContext.tsx†L1-L138】
- عميل API مبني على Axios مع حقن تلقائي للتوكن، دعم ذاكرة تخزين مؤقت قابلة للتكوين، وخطاف `useApi` لتبسيط جلب البيانات مع مراقبة الحالة والأخطاء.【F:frontend/src/lib/api.ts†L1-L88】
- دليل الواجهة الأمامية يحدد قواعد الأداء (تحميل الخطوط، إعادة استخدام تصميم الزجاج، إدارة الأصول عبر alias `@`) ويشير إلى اعتماد Vitest + Testing Library للاختبارات التفاعلية باللغتين.【F:frontend/README.md†L1-L44】
- نموذج لوحة التحكم يشرح استهلاك واجهة `/dashboard`، استخدام الترجمة الثنائية، والفجوات المقترحة (Endpoint إضافي لحرارة الإقبال).【F:frontend/src/modules/dashboard/README.md†L1-L16】

## 4. سير العمل والوظائف الرئيسة
- مصادقة المستخدم: تسجيل الدخول عبر `/api/v1/login`، جلب المستخدم الحالي عبر `/api/v1/me`، وتخزين بيانات الدور في السياق لتمكين الحماية على مستوى الواجهة (حماية المسارات والمكونات).【F:backend/app/Http/Controllers/Api/V1/AuthController.php†L17-L78】【F:frontend/src/contexts/AuthContext.tsx†L58-L138】
- لوحة التحكم والتحليلات: الواجهة تستدعي `/dashboard` و`/analytics` لتحميل ملخص الإحصاءات، مع إمكانية استدعاء `/analytics/forecast` للتنبؤات، وتستخدم الخرائط التفاعلية عبر تكوين خارجي من `/integrations/maps/configuration`.【F:backend/routes/api.php†L86-L104】【F:backend/app/Http/Controllers/Api/V1/AnalyticsController.php†L1-L119】【F:README.md†L14-L38】
- إدارة البيانات الأساسية (لجان، متطوعين، ناخبين...): جميعها متاحة عبر REST كامل في الواجهة الخلفية، مع دعم استيراد/تصدير للناخبين، وتعيين المتطوعين للفرق. بعض الوحدات في الواجهة ما تزال تنتظر ربط حقيقي كما ذُكر في مراجعة CRUD.【F:backend/routes/api.php†L93-L116】【F:CRUD_API_REVIEW.md†L18-L52】
- التكاملات الخارجية: بوابة `/api/v1/integrations` توفر بيانات جغرافية ونتائج انتخابية حية مع إمكانات التخزين المؤقت والبث عبر WebSockets، وتُدار مفاتيح الخدمة عبر متغيرات البيئة المذكورة في الوثائق الخلفية.【F:backend/README.md†L63-L109】【F:backend/routes/api.php†L105-L111】
- الأتمتة والتنبيهات: واجهات `automation/config` لإدارة المهام المجدولة، ومركز إشعارات في الواجهة يدعم التصفية وتعيين الإشعارات كمقروءة، مع توصيات الوثائق لتفعيل المحرك الذكي في الإصدار v1.6.【F:backend/routes/api.php†L90-L104】【F:README_UNIFIED.md†L86-L134】

## 5. الاختبارات وضبط الجودة
- الواجهة الأمامية تعتمد Vitest وTesting Library لاختبار المكونات المشتركة والتأكد من دعم RTL/LTR، كما توفر سكريبت `npm run test` لتشغيل الحزمة كاملة.【F:frontend/README.md†L25-L37】
- الواجهة الخلفية تتضمن إعدادات PHPUnit في `phpunit.xml` (لم يتم تفصيل تغطية الاختبارات في الوثائق الحالية)؛ يُوصى بتوسيع الاختبارات الآلية للعمليات الحرجة (المصادقة، التقارير المالية، التوقعات).

## 6. المخاطر والتوصيات
- استكمال ربط الوحدات التي تعتمد بيانات ثابتة مع واجهات `/api/ec/*` الحقيقية لضمان توحيد المصادقة وتدفق البيانات.【F:CRUD_API_REVIEW.md†L18-L52】
- إضافة اختبارات تكامل بين الواجهة والواجهة الخلفية خاصة لوحدة التحليلات والتكاملات الخارجية لضمان ثبات مخطط الاستجابة.
- تحديث وثائق Laravel الافتراضية في `backend/README.md` بوثيقة مخصصة توضح تعليمات التشغيل والتهيئة الخاصة بالمشروع.
- توسيع قدرات المراقبة لتشمل إشعارات زمنية على التوقعات (مثلاً عندما يتجاوز `coverage_gap` نسبة معينة) لزيادة فاعلية محرك التنبيهات.

## 7. خلاصة
المشروع يقدم منصة انتخابية متكاملة بواجهة حديثة ودعم ثنائي اللغة، مع واجهة برمجة غنية تشمل التحليلات، الأتمتة، وإدارة شاملة للكيانات الانتخابية. الاهتمام القادم يجب أن يتركز على إزالة البيانات الوهمية، تعزيز الاختبارات، وتوثيق طبقة البنية التحتية الخلفية لتسريع الاعتماد الإنتاجي.
